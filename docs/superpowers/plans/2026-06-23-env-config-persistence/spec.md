# Spec — 环境配置体系 + dev 本地持久化 + dev-only 隔离(Plan B / 阶段 2)

> WHAT / WHY。零实现细节(技术栈/文件名/env schema 归 design.md)。地基 [ADR-021](../../../adr/ADR-021-env-config-system.md)(Accepted)。

## 出口与范围
- **关哪个**:配置/环境治理债——当前无单一配置源,导致一次启动里部分服务连真阿里云、部分连本地("串味");dev 数据重启即丢。
- **In**:① 单一配置源(选一个环境 = 整套生效)② dev 完全本地且数据持久 ③ dev-only 服务与基础依赖可分别启停(隔离)④ test/prod 环境**骨架 + 缺密钥不静默**。
- **Out / 推迟**:阿里云 ECS 实际搭建(阶段 3 / Plan C,[ADR-022](../../../adr/ADR-022-ci-on-aliyun-ecs.md));把服务内 `os.environ` 散读改成 typed 配置注入(渐进迁移,vN+);CI 部署形态变更(本轮 CI 维持现状)。
- **与 Sprint 对齐**:基础设施治理,服务于 S1 已交付能力的可靠本地运行;不新增业务出口。

## 用户故事(按优先级,可独立测试)

### US1 — 一键起完全本地环境、绝不串味(P1)
**Why P1**:这是本轮起因。半云半本地会把本地操作误写进真云桶(数据/审计污染),是正确性与安全问题,最高优先。
**可独立测试**:只做 US1(单一源 + local 档)即是一个可演示 MVP——起服务后能证明全栈同源本地。
- **AC1 (G/W/T)**:Given 选择本地环境,When 一键起全部服务,Then 每个服务的对象存储端点都指向本地(localhost),**无任何**指向阿里云的端点。
- **AC2**:Given 想换环境,When 改动**一处**环境选择,Then 整套服务随之切换,不需要在多个文件里分别改。
- **AC3**:Given 同一份配置定义,When 查看"某服务连哪个存储/哪个下游",Then 该信息**只在一个地方**定义,不存在两处各写一份、可能漂移的副本。

### US2 — dev 数据重启不丢(P2)
**Why P2**:开发连续性;但晚于"先别污染真云"。
**可独立测试**:起服务→造数据→重启(不清卷)→数据仍在,独立可验。
- **AC1**:Given 在本地上传/注册了数据集并创建了用户,When 重启依赖容器(不执行"清空数据"的停法),Then 之前的对象、数据目录条目、登录用户**都还在**。
- **AC2**:Given 确实想清空重来,When 使用"带清空"的停法,Then 数据被清除(保留一条显式的毁灭性操作通道)。

### US3 — 基础依赖与 dev-only 服务分别启停(P3)
**Why P3**:为阶段 3(CI 只需基础依赖、不需要 dev-only 辅助服务)铺隔离;本轮先把边界划清。
**可独立测试**:两个启动档各起一次,核对起了哪些容器。
- **AC1**:Given 只想要基础依赖(对象存储 + 身份 + 其 DB),When 用"基础档"启动,Then 只起基础依赖,**不**起 dev-only 的数据目录服务与 API 文档聚合页。
- **AC2**:Given 要完整本地开发,When 用"完整档"启动,Then 基础依赖 + dev-only 服务全部起来。

### US4 — 非本地环境缺密钥时显式失败(P2)
**Why P2**:防"占位当真值"静默连错/连空,是安全红线;但本轮不真连云,故 P2。
**本轮验收层级**:test/prod 环境档本轮**不接入真实启动**(它们是阶段 3 的输入产物,见 Assumptions);本能力由**配置加载**这一环节保证、以**单测**断言,而非整启动链路。
**可独立测试**:对 test 环境档执行配置加载且不提供密钥 → 加载即报错,独立可验。
- **AC1**:Given 选择测试/生产环境,When 必需密钥未由外部注入,Then **配置加载立即失败并指出缺哪个**,绝不静默使用空值或占位继续。
- **AC2**:Given 选择本地环境,When 未额外提供任何密钥,Then 仍能用内置的本地固定开发值正常起(本地不因缺密钥受阻)。

### Edge Cases
- 当某服务的某项配置在所选环境档里缺失时会怎样?→ 必需项缺失应**显式报错**(对齐 US4),非必需项用记录在案的默认值。
- 当同一端口已被上一次遗留进程占用时会怎样?→ 启动应可观察到冲突(沿用现有按端口探测),不静默连到错误的旧进程(本轮不扩此能力,仅不回退)。
- 当本地与测试两套配置同时存在时,如何保证不会误用?→ 由"选定的单一环境"决定,任一时刻只有一个环境档生效。
- 当持久化卷里是旧格式数据、镜像升级后会怎样?→ 属已知风险,记入 Assumptions;本轮不做迁移工具。

## 功能需求(MUST,可测)
- **FR-001** 系统 MUST 提供**单一配置源**:每个环境(本地/测试/生产)各有一份独立的配置定义,描述该环境下各服务的连接目标、端口、存储、身份等。
- **FR-002** 系统 MUST 让"选择哪个环境"成为**单一开关**;切换环境只改这一处,全部服务随之一致生效。
- **FR-003** 系统 MUST 消除配置的重复定义——同一项配置不得在两处各写一份(消除漂移源)。
- **FR-004** 系统 MUST 保证一次启动中**所有服务属于同一环境**;不得出现部分服务连本地、部分连云的混合状态。(本轮经**本地启动路径**强制:单一源使一次启动只取一个环境档;test/prod 的真实启动接入属阶段 3,见 Assumptions。)
- **FR-005** 系统 MUST 让 dev 的对象存储、数据目录、身份用户在**重启后保留**,并保留一条**显式的"清空"**操作。
- **FR-006** 系统 MUST 支持**两档启动**:仅基础依赖、以及基础依赖 + dev-only 服务。
- **FR-007** 配置 MUST **不在仓库存放真实密钥**;本地档可内置本地固定开发值,测试/生产档对必需密钥用占位,缺失即**启动失败**(FR 对应 US4)。
- **FR-008** 本轮变更 MUST **不破坏现有 CI**(现有持续集成沿用现状仍通过)、**不改变服务读取配置的现有方式**(兼容,不做大改写)。
- **FR-009** 测试/生产环境档 MUST 至少建出**骨架**;未定项以**显式标注**呈现,不得静默留空。

## 关键实体(概念)
- **环境档(Profile)**:一个具名环境(本地/测试/生产)的完整配置集合。
- **环境选择开关**:决定当前生效哪个环境档的单一入口。
- **密钥占位**:配置中"值来自外部、不入库"的标记;本地可有固定开发值,非本地缺失即失败。
- **持久化数据**:dev 重启后需保留的三类——对象存储内容、数据目录条目、身份用户。
- **启动档**:基础依赖 / 完整(含 dev-only)两种启动范围。

## Success Criteria(可度量、技术无关)
- **SC-001**:任选一次本地启动,核对全部服务的存储端点——**100% 指向本地、0 个指向云**。
- **SC-002**:本地造数后按"不清空"方式重启,三类数据(对象/目录/用户)**全部保留**(逐项可见)。
- **SC-003**:切换环境**只需改 1 处**;由该处即可确定全栈所连环境。
- **SC-004**:同一配置项在仓库中**有且仅有 1 处**定义(无重复副本)。
- **SC-005**:对测试环境档执行配置加载且缺必需密钥 → **加载即失败并指出缺失项**(由配置加载单测断言;test/prod 档本轮不接入真实启动)。
- **SC-006**:基础档与完整档启动起的容器集合**符合各自定义**(基础档不含 dev-only)。
- **SC-007**:新增配置加载单测纳入测试套件并**全绿**;静态检查确认新配置模块**不引入反向依赖**;两处重复配置已删(可 grep 证明单一源);现有质量门禁(生成/静态检查/测试)仍全绿。
- **SC-008**:本地真跑一次数据作业(提交→成功),证明 detached worker 子进程经继承拿到对象存储凭据(桥接注入集回归到 worker 路径)。

## Assumptions
- 本地固定开发值(对象存储账号/会话密钥/客户端密钥等)**非真实密钥**,入库可接受(对齐宪法允许 dev 固定值)。
- 测试/生产档本轮**只建骨架**,不要求真连云;真连云属阶段 3。
- 服务读取配置的现有机制保持不变,新体系通过**兼容桥接**向其供值(实现细节见 design.md;此处仅声明"不改服务读法")。
- 持久化只保证"不主动删";镜像大版本升级导致的数据格式迁移**不在本轮**。
- dev 各依赖(对象存储/身份及其库/数据目录)各自的**持久化位置**需以实测确认(design.md 列为待探查项 + 决策规则)。
