# Spec(需求):企业模板副本(Agent Template Copies)

> 需求层(WHAT/WHY)。**禁**技术栈/契约 schema/实现(归 design.md / tasks)。
> **状态**:Draft · **输入**:owner —— "内置的 agent 可以直接编辑或删除;逻辑应该是平台的模板不改变,每个企业启动的时候默认复制一份,企业修改的是企业复制的那份。" + 本次对话拍定:**惰性(首次进库时)种一次**、**内置模板在企业侧彻底不显示**。
> **关联**:承接 [ADR-027](../../../adr/ADR-027-agent-library.md)(智能体库)、9a(omnigent 集成)。遵循 constitution §1(隔离)、§2.4(can())、§6.1(审计)。

## Goal & 价值
- **目标**:把智能体库的模型从「平台内置模板全局共享**只读** + 本企业创建」升级为「**每企业首次进库时默认获得全套平台模板的可编辑副本**」。企业管理员编辑/删除的是**本企业自己的副本**;平台模板是**不可见的种子源**,企业侧任何操作都**不触碰**它。
- **价值**:满足 owner "内置也能直接改/删" 的诉求,同时**不破坏多企业隔离**——企业改的是自己那份,别的企业和平台模板都不受影响。消除"内置只读"这一别扭约束。
- **成功长这样**:alice 首次进「智能体库」,自动看到一整套本企业可编辑的智能体(内容来自平台模板);她直接改其中一个的提示词、删掉不想要的那个——都成功、不再报"内置不可改";另一个企业 bob-corp 进库看到的是**它自己**的一套副本,alice 的改动/删除对它毫无影响;平台模板本身从未改变。

## 范围
- **In(本版做)**:
  - 企业**首次进「智能体库」**时,惰性把**全套平台模板**复制成本企业智能体(带企业归属、可编辑/删除)。**一次性**:种过就不再种。
  - 企业侧列表**只显示本企业的副本**(全部可编辑/删除);**平台内置模板不再并列显示**(它只作种子源)。
  - 编辑/删除**复用现有本企业智能体的编辑/删除**能力(企业管理员门;成员无入口)。
- **Out / 推迟(vN+)**:
  - 删掉某副本后的「从模板恢复 / 再添加」入口。
  - 平台**后续新增**的模板**回填**给已种企业。
  - platform-admin **真改平台模板**(本方案不需要;若将来要做平台级模板策展,另立 spec)。
  - per-agent 凭据 / vault:维持现状——副本继承**平台全局共享订阅**,不引入按智能体的凭据。

## User Scenarios & Testing

### User Story 1 — 首次进库自动获得全套可编辑副本 (P1)
企业用户第一次打开「智能体库」时,系统**自动**为该企业准备好一整套智能体——内容来自平台模板,但**归本企业所有、可被本企业管理员编辑/删除**。

- **Why P1**:这是整个模型转变的核心;没有它,"内置可改"无从谈起。
- **可独立测试**:一个**从未进过库**的企业,其管理员登录 → 进「智能体库」→ 列表里出现 = 平台模板数量的一批智能体,每条都带「本企业」标记、都能点「编辑/删除」。
- **验收**:
  1. **Given** 某企业此前从未进过智能体库 **When** 其成员首次打开库 **Then** 列表里出现与平台模板一一对应的一套**本企业**智能体(名字/基底/提示词继承自模板)。
  2. **Given** 首次进库已种好副本 **When** 管理员查看任一条 **Then** 它标「本企业」、可编辑、可删除(不再有"内置只读")。
  3. **Given** 副本继承自模板 **When** 用它建会话对话 **Then** 行为与原模板一致(同基底、同全局共享订阅)。

### User Story 2 — 企业管理员编辑/删除本企业副本(含"原内置") (P1)
企业管理员对库里任一智能体(现在都是本企业副本,包括那些内容来自平台模板的)都能**直接编辑或删除**,改动**只影响本企业**。

- **Why P1**:owner 的原始诉求 "内置的 agent 可以直接编辑或删除"。
- **可独立测试**:管理员改一个"源自模板"的副本的提示词并保存 → 库里该条内容更新;删另一个 → 库里消失。全程无"内置不可改/不可删"报错。
- **验收**:
  1. **Given** 管理员在库中选一个源自模板的副本 **When** 编辑其名字/提示词并保存 **Then** 保存成功,库中该条更新;**平台模板与其它企业的同源副本不变**。
  2. **Given** 管理员选一个副本 **When** 删除 **Then** 该副本从本企业库消失;**平台模板仍在**(供未来新企业种子)。
  3. **Given** 登录者**非**管理员 **When** 查看库 **Then** 看不到"编辑/删除"入口;**When** 绕过界面直接调改/删接口 **Then** 被拒(无权)。

### User Story 3 — 一次性种子:删了不复活 (P1)
种子只发生一次。企业把某些副本删掉(甚至全删光)后,再次进库**不会**被重新种回来。

- **Why P1**:否则"删除"形同虚设——删了又长出来,是明显的功能缺陷。
- **可独立测试**:企业首次进库(种好 N 个)→ 删掉其中若干 → 刷新/重进库 → 被删的**不复现**,数量保持在删后的值。
- **验收**:
  1. **Given** 企业已种过种子且删了 k 个 **When** 重新进库 **Then** 列表只剩 N−k 个,被删的不复活。
  2. **Given** 企业把副本**全删光** **When** 重新进库 **Then** 列表为空(不被重新种满)。

### User Story 4 — 跨企业隔离:各种各的、平台模板不被触碰 (P1)
每个企业种自己的一套副本;一个企业的编辑/删除对**其它企业的副本**和**平台模板**都无影响;企业之间互相看不到对方的副本。

- **Why P1**:多租户底线(宪法 §1)。
- **可独立测试**:企业 A、B 各自首次进库各得一套;A 改/删自己的 → B 的那套和平台模板都不变;A、B 互相看不到对方副本。
- **验收**:
  1. **Given** A、B 各已种子 **When** A 编辑/删除其副本 **Then** B 的副本集合与内容不变,平台模板不变。
  2. **Given** A 的某副本标识 **When** B 用户拿它去看/建会话 **Then** 被拒(不可见/无权)。

### User Story 5 — 成员首次进库也能触发种子(系统级),但无编辑权 (P2)
即便第一个进库的是**普通成员**(非管理员),种子也照常发生(它是系统为企业做的初始化,不是"用户建 agent");但成员**仍不能**编辑/删除。

- **Why P2**:保证种子不因"谁先进库"而缺失;不阻塞 P1 演示故 P2。
- **可独立测试**:一个从未进库的企业,让其**普通成员**第一个进库 → 副本被种出、成员能看到;但成员**无编辑/删除入口**,直调改/删接口被拒。
- **验收**:
  1. **Given** 企业未种子且第一个进库者是普通成员 **When** 他打开库 **Then** 副本被种出并可见。
  2. **Given** 同上成员 **When** 尝试编辑/删除 **Then** 无界面入口且直调接口被拒(权限不变)。

### Edge Cases
- 当企业**把副本全删光**后再进库时会怎样?→ 见 US3:不复活(种子标记已存在)。
- 当**两个请求并发**触发同企业首次进库时会怎样?→ 必须**只种一次**,不得双份。
- 当**平台模板集为空**时首次进库会怎样?→ 种 0 个,但视为"已种子",不反复尝试。
- 当种子**中途失败**(部分副本已建)时会怎样?→ 不得留下"半套且标记已完成"的状态误导后续;需能安全重试补齐或整体不标记完成。
- 当某企业在本功能上线**之前就已建过本企业智能体**(历史遗留,如 dev 的 ent-demo 已有测试建的本企业 agent)时,首次进库会怎样?→ 需明确:是"照种全套模板副本、与已有并存",还是"视为已初始化、补标记跳过种子"。(见 Assumptions;design 定策略。)

## Success Criteria
- **SC-001**:某从未进库的企业,其成员首次进库后,库中本企业副本数量 = 平台模板数量;每条可编辑、可删除。
- **SC-002**:管理员编辑/删除任一"源自模板"的副本**成功**,不出现"内置不可编辑/删除"类错误。
- **SC-003**:企业删掉 k 个副本(含全删)后重进库,列表数量保持在删后的值,被删项不复现。
- **SC-004**:企业 A 的编辑/删除完成后,平台模板内容与企业 B 的副本集合/内容**逐条不变**。
- **SC-005**:首次进库的种子过程在 owner 主观上"无明显卡顿"(目标:常规模板数量下端到端 ≤ 3 秒返回列表)。

## Assumptions
- **复制内容**:副本继承平台模板的**基底(harness)、系统提示词、描述/展示名**;**不带 per-agent 凭据**——沿用平台全局共享订阅(与现状一致)。
- **模板集时点固定**:种子时刻的平台模板集即为该企业的初始集;平台**后续新增**的模板**不回填**给已种企业(推迟)。
- **种子触发面**:进「智能体库」列表这一读操作触发;种子是**系统级初始化**,不受"用户建 agent 需企业管理员"的门限制(但用户对副本的编辑/删除权限**不变**)。
- **历史遗留企业**(上线前已有本企业 agent):默认策略待 design 拍定;倾向"补标记、视为已初始化,不再额外种全套"以免与既有重复(owner 在 design/DoR 处确认)。
- **种子已完成标记**:需要一处**每企业持久标记**来保证"只种一次";具体载体/路径归 design。
