# Spec(需求):智能体库(Agent Library)

> 需求层(WHAT/WHY)。**禁**技术栈/契约 schema/实现(归 design.md / tasks)。
> **状态**:Draft · **输入**:owner —— "1)需要一个页面叫智能体库,展示所有智能体;2)可以创建智能体和设置智能体的配置(参考 omnigent 智能体配置、默认按 omnigent 自带模板),只有企业管理员可以设置;3)对话窗口开始时选择智能体,对话开始后不能变更。" + 本次对话拍定:**凭据一律用全局共享订阅**(无 per-agent 凭据)、**每企业一套**、隔离在 BFF。
> **关联**:承接 9a(omnigent 集成 + 对话窗)、ADR-026;新 ADR-027(智能体库)。

## Goal & 价值
- **目标**:在控制台加一个「智能体库」——展示本企业可用的智能体;**企业管理员**可创建/配置自定义智能体(基于 omnigent 模板:名字/模型/系统提示词);用户在**对话开始时选一个**智能体,**开始后锁定**。
- **价值**:把 9a 的"通用对话"升级成"可按场景定制的多智能体"——企业能沉淀自己的客服助手/代码助手等;为后续(数据工具、per-agent 凭据)留接口。
- **成功长这样**:企业管理员 alice 建一个"客服助手"(自定义提示词)→ 同企业普通成员 bob 进对话窗,从库里选"客服助手"开聊、回复符合那段提示词;另一企业的人看不到这个智能体;非管理员根本看不到"新建"入口。

## 范围
- **In(本版做)**:
  - 「智能体库」页:列出本企业可见智能体(omnigent **内置模板** + 本企业**创建的**)。
  - 企业管理员**创建**自定义智能体:名字 + 基底模板(omnigent 内置)+ (可选)模型 + (可选)系统提示词。仅企业管理员可建/改。
  - 对话窗**开始时选**智能体(替换现写死的默认);**会话创建后锁定**,不可中途换。
  - **每企业隔离**:用户只见/用本企业的智能体(+ 全局内置模板)。
- **Out / 推迟**:
  - **per-agent 凭据 / secret vault / per-agent 订阅**:本版智能体**一律用平台全局共享订阅**(claude),不引入按智能体的凭据。→ 生产上 KMS 时再议。
  - 多 provider 全局凭据扩展(codex/openai 全局 token):可选、不在本版。
  - 编辑/删除内置模板;智能体共享/跨企业授予;数据工具/MCP/承重墙(=后续)。

## User Scenarios & Testing

### User Story 1 — 对话开始选智能体 (P1)
用户进对话窗,**开始新会话时从库里选一个智能体**,然后开聊;**这一会话固定用所选智能体**,中途不能换。

- **Why P1**:这是"多智能体"对用户的核心可见价值;没有它,库只是个摆设。
- **可独立测试**:一个用户登录 → 进 Workspace → 新会话弹出智能体选择 → 选"客服助手" → 发消息 → 回复符合该智能体设定,即通过。
- **验收**:
  1. **Given** 用户在 Workspace **When** 点"新会话" **Then** 先要求选一个智能体(默认可预选一个),选定后才建会话。
  2. **Given** 会话已用智能体 X 建好 **When** 用户继续对话 **Then** 全程用 X;**界面无"换智能体"入口**(开始后锁定)。
  3. **Given** 用户新建另一个会话 **When** 选智能体 Y **Then** 新会话用 Y,与上一会话独立。

### User Story 2 — 企业管理员创建/配置智能体 (P1)
**企业管理员**在智能体库创建自定义智能体:填名字、选一个 omnigent 内置模板作基底、(可选)改模型、(可选)写系统提示词。**非管理员不能创建/配置。**

- **Why P1**:owner 明确要"创建智能体 + 只有企业管理员可设置";这是本功能的存在理由。
- **可独立测试**:企业管理员登录 → 智能体库 → 新建"客服助手"(提示词="你是客服…")→ 库里出现它;普通成员登录 → 库里能看到它但**没有"新建"按钮**。
- **验收**:
  1. **Given** 登录者是企业管理员 **When** 提交"新建智能体"(名字+模板+提示词) **Then** 创建成功、库里可见、可用于建会话。
  2. **Given** 登录者**不是**企业管理员 **When** 查看智能体库 **Then** **看不到"新建/配置"入口**;**When** 绕过界面直接调创建接口 **Then** 被拒(无权)。
  3. **Given** 管理员建智能体 **When** 留空模型/提示词 **Then** 用所选**内置模板的默认**(omnigent 自带)。

### User Story 3 — 跨企业隔离 (P1)
不同企业各有各的智能体库;**一个企业看不到、也用不了另一个企业创建的智能体**(内置模板对所有企业共享可见)。

- **Why P1**:多租户底线(宪法 §1);和 P1 同级。
- **可独立测试**:企业 A 的管理员建"A 客服";企业 B 的用户在库里**看不到"A 客服"**,且用它的标识也**建不了会话**。
- **验收**:
  1. **Given** A 企业建了智能体 X **When** B 企业用户查看库 **Then** 列表里**无 X**(但有全局内置模板)。
  2. **Given** B 企业用户(猜到)X 的标识 **When** 用 X 建会话 **Then** 被拒(无权/不可见)。
  3. **Given** 内置模板 **When** 任一企业用户查看 **Then** 都能看到、都能用(全局共享)。

### User Story 4 — 配置审计 (P2)
企业管理员创建/配置智能体的动作被审计记录(谁、何时、对哪个智能体、做了什么)。

- **Why P2**:宪法 §6.1 要求 mutation/admin 动作审计;不阻塞 P1 演示,故 P2。
- **可独立测试**:管理员建一个智能体 → 审计存储里出现一条对应记录。
- **验收**:**Given** 管理员建/改智能体 **When** 动作完成 **Then** 审计落一条(actor/企业/action/资源/decision)。

### Edge Cases
- 选智能体后**建会话失败**(沙箱起不来)时?→ 明确反馈,不静默卡死;会话不残留半成品。
- 管理员建智能体时**名字与已有重名**?→ 明确提示(拒绝或覆盖,按 design 定),不静默。
- 用户**对话进行中**试图换智能体(直接调接口)?→ 被拒/无此入口(锁定不变式)。
- 智能体配置**引用了平台没注入凭据的 harness**(如 codex 而平台只注了 claude 订阅)?→ 要么库只提供"可用"的模板,要么明确报"该智能体不可用",不伪装成功。
- **非管理员**直接调创建/配置接口?→ 服务端 403(不靠前端藏按钮兜底)。
- 用户**未登录/会话过期**访问库或创建?→ 跳登录/拒。

## Requirements(功能需求,可测)
- **FR-001**:用户 MUST 能在「智能体库」看到**本企业可见**的智能体(全局内置模板 + 本企业创建的)。
- **FR-002**:用户 MUST 在**对话开始时选**一个智能体;会话创建后该会话 MUST NOT 更换智能体(锁定)。
- **FR-003**:**仅 enterprise-admin** MUST 能创建/配置智能体;非管理员 MUST 被拒——**前端无入口 + 服务端授权拒绝(不靠前端兜底)**。
- **FR-004**:创建智能体的配置 MUST 含**名字** + **基底模板**(omnigent 内置);MAY 含**模型**、**系统提示词**;留空项 MUST 用所选内置模板的默认。
- **FR-005**:智能体 MUST 按**企业隔离**——用户 MUST NOT 看到或使用**他企业**创建的智能体;内置模板对所有企业共享可见。
- **FR-006**:智能体 MUST 用平台**全局共享订阅**运行;本版 MUST NOT 引入 per-agent 凭据 / vault。
- **FR-007**:创建/配置/删除等**变更** MUST 写审计(actor、企业、action、资源、decision)。
- **FR-008**:授权决策 MUST 经统一出入口(`can()`),MUST NOT 散落 ad-hoc 比较(宪法 §2.4)。

### 关键实体(概念级)
- **智能体(Agent)**:一个可复用的对话角色配置;含 名字 / 基底模板(harness)/ 模型 / 系统提示词;**归属一个企业**(内置模板=全局);用户对话时选用。
- **企业(Enterprise)**:KC Organization 不透明 alias;智能体的归属与可见性边界。
- **会话(Conversation)**:用户与某智能体的一段对话;**绑定一个智能体且开始后不可变**。

## Success Criteria
- **SC-001**:企业管理员能在库里**创建一个自定义智能体**(名字+模板+提示词)并立即在列表可见、可用于建会话。
- **SC-002**:用户**对话开始可从库选智能体**,选定后该会话**全程固定**用它(无中途更换入口)。
- **SC-003**:**跨企业隔离可验证**——A 企业的智能体不在 B 企业列表;B 用它的标识建会话被拒。
- **SC-004**:**非管理员无创建能力**——UI 无"新建"入口,且直接调创建接口被服务端拒(403)。
- **SC-005**:库里(可用模板的)智能体**用全局共享订阅就能正常对话**,无需任何 per-agent 凭据。

## Assumptions(假设与依赖)
- 依赖 **9a** 已交付:omnigent 集成、BFF 反代(T4)、managed 沙箱隔离、**全局共享订阅**(`secrets/omnigent.token`→`CLAUDE_CODE_OAUTH_TOKEN`)。
- **omnigent 无运行时"建可复用 agent"端点**(探针 `spikes/agent-create.md` 实测钉死);经**小 fork** 加 `POST /v1/agents`(暴露 omnigent 自身启动期内部函数;ADR-027)。
- **企业归属由 BFF 维护**(omnigent 租户无关);隔离在 BFF 边界做。
- 凭据**全局共享**(当前仅 claude 订阅);per-agent 凭据 / 多 provider / vault 推迟。
- 智能体"开始后锁定"=BFF **不反代** omnigent 的 `switch-agent` 端点(原生有,我们不暴露)。
