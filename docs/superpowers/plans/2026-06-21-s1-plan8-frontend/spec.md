# Spec(需求):S1 Plan 8 — 数据域控制台(图形界面)

> 需求层(WHAT / WHY)。**禁**技术栈 / 契约 schema / 实现细节(归 design.md / tasks)。面向非技术干系人可读。
> 结构参考 spec-kit `speckit.specify`。不明确处 `[NEEDS CLARIFICATION]`(≤3),能默认的默认并记入 Assumptions。

**状态**:Draft · **关联出口 / Sprint**:S1 出口⑤(真 GUI 经 API 端到端调通);S1(已延长);ADR-019 · **输入**:"把数据域做成能登录、能点、能用的图形控制台,关闭出口⑤"

## Goal & 价值
- 给数据域的第一个客户一个**能登录、能点、能用**的图形控制台:管理数据集、浏览数据目录、上传数据、提交并跟踪数据准备作业、查看账户。
- 价值:证明平台能力可被**真实用户经界面**端到端使用(而不止 API / 脚本);交付首个可演示、可交付客户的产品界面;关闭 S1 出口⑤。
- 视觉 / 信息架构基线:高保真原型 `docs/superpowers/prototypes/2026-06-22-data-domain-hifi.html`(owner 已确认),实现照此搭。

## 范围
- **In(本 plan 做)**:登录 / 会话 / 登出 · 可折叠导航外壳 · 我的账户 · 数据集(列表 / 搜索 / 详情 / 上传)· 数据目录(层级浏览 + 详情)· **从数据集/目录一键发起作业** · 数据管线(作业列表 + 跟踪 + 失败排查)· 创建作业。
- **Out / 推迟(vN+,带理由)**:
  - SQL 查询、另存为 —— 需查询引擎。
  - **数据集 / 作业的管理动作**(删除 / 重命名 / 改属性 / 打标签 / 取消作业 / 重跑)—— 后端 metadata 无 DELETE/PATCH、作业无 cancel(均 backlog);本轮界面**只读 + 创建**,不提供编辑 / 销毁。
  - **数据集 / 产物的下载与导出** —— presigned GET 下载机制尚无 ADR、未实现;本轮产物以 **URI / 位置呈现(可见不可取)**。
  - 数据资产**权限 / 策略管理界面**(跨用户组授权)—— 需 ACL,v2。
  - **自然语言数据探查助手** —— 需 Agent 平台,v2。
  - **血缘(lineage)展示** —— 后端尚无血缘数据源;详情页本轮不出现血缘维度(不画空 Tab)。
  - 高级搜索 / 排序 / 分页、移动端适配。

> **组织模型(硬约束,反复确认)**:平台 → 企业 → **用户组** → 用户。**用户组是访问权限维度,不是数据归属或上传目的地**:上传**不让用户选组**(归属由用户身份决定),界面**不把用户组当数据的"所在地"**展示。跨用户组授权共享属 v2。

## User Scenarios & Testing *(必填)*

> 用户故事按重要性排优先级,每个可独立测试(只做 P1 也是可演示、能关出口⑤本质的 MVP 切片)。

### User Story 1 — 登录并查看我的数据(P1)

作为某企业的用户,我用企业分配的账号登录,进入数据域控制台,看到**我有权访问的数据集**列表,确认平台能力可经界面真实使用。

- **Why this priority**:这是出口⑤ 的本质——"真 GUI 经 API 端到端调通"。只要这条成立,就有可演示、可交付客户的最小产品,并验证了登录 / 会话 / 授权过滤 / 数据读取整条链。
- **可独立测试**:用真账号登录 → 看到列表且只含本人有权的数据 → 进一项看详情 → 登出。无需上传 / 作业等即可证伪。
- **验收场景**:
  1. **Given** 未登录 **When** 访问任一受保护页面 **Then** 被引导登录;成功后回到目标页,顶栏显示用户名与所属企业(显示名)。
  2. **Given** 已登录 **When** 打开"数据集" **Then** 看到列表(名称、描述、格式、样本数、大小、创建人),可按名称搜索。
  3. **Given** 列表渲染 **When** 检视 **Then** 只出现我有权访问的数据集;跨企业 / 跨组数据**永不出现**;界面**不出现任何内部标识**(如 e- / g- 前缀 ID)。
  4. **Given** 一个数据集 **When** 进入详情 **Then** 展示其已有属性(名称 / 描述 / 格式 / 样本数 / 大小 / 创建人 / 位置 / 是否共享);无后端数据的维度(如血缘)本轮不出现。
  5. **Given** 已登录 **When** 登出 **Then** 会话结束、回登录态;旧会话再访问受保护页 → 被要求重新登录。

### User Story 2 — 上传原始数据集(P2)

作为用户,我在数据集页把一份原始数据(可能很大)上传到平台供后续清洗,过程可见、可恢复。

- **Why this priority**:有数据才能跑管线,上传是闭环入口。但 P1 已能独立交付,故次之。
- **可独立测试**:登录后发起一次上传 → 完成后数据集出现在列表(标记可用)→ 可被作业选为源。
- **验收场景**:
  1. **Given** 已登录 **When** 在数据集页发起上传(填名称、选文件,**不选组**)**Then** 过程显示进度,完成后数据集出现在列表并可用。
  2. **Given** 大文件 **When** 上传中 **Then** 显示进度;失败可重试;凭据 / 通行证过期可无缝续传而非从头来。
  3. **Given** 上传中途失败或未完成 **When** 查看该数据集 **Then** 它**不显示为可用**(无假成功),遗留半成品被系统清理。

### User Story 3 — 浏览数据目录(P2)

作为用户,我按"企业 → 数据源 → 数据域"层级浏览平台已登记的数据资产,了解归属、格式与位置。

- **Why this priority**:出口⑤ 演示必经目录浏览(owner 决);目录是"发现资产"的主入口,后端已就绪、原型为两栏主屏。
- **可独立测试**:打开数据目录 → 展开 / 折叠层级树 → 选中一个数据域 → 右侧看到其下资产与概览。
- **验收场景**:
  1. **Given** 已登录 **When** 打开"数据目录" **Then** 左侧按层级树**可展开 / 折叠**。
  2. **Given** 展开到某数据域 **When** 选中它 **Then** 右侧列出其下资产(名称、创建人、格式、登记时间、是否共享)与概览。
  3. **Given** 浏览目录 **When** 检视 **Then** 只展示我有权访问的资产;某层无资产时呈现明确空状态。

### User Story 4 — 从数据集/目录发现并发起作业(P2)

作为用户,我在看一个就绪数据集(于数据集列表或数据目录)时,直接对它发起数据准备作业,而不必再去别处手填源。

- **Why this priority**:这是把"有数据"(US2)和"用数据建作业"(US5)缝成闭环的关键一针;SC-002 的端到端闭环靠它成立。原型详情面板已有"用于创建作业"入口。
- **可独立测试**:在数据集/目录选中一个就绪数据集 → 点"用于创建作业" → 创建作业页的**源已预选为该数据集** → 提交成功。
- **验收场景**:
  1. **Given** 一个 ready 数据集 **When** 在其详情/行点"用于创建作业" **Then** 跳到创建作业,源已预选为它。
  2. **Given** 源已预选 **When** 补齐参数并提交 **Then** 作业被接受、进入"数据管线"。

### User Story 5 — 提交并跟踪数据准备作业到成功(P2)

作为用户,我提交一个数据准备作业,并在界面上看着它跑到成功、拿到产物。

- **Why this priority**:平台核心价值产出(把原始数据清洗成可用数据集)的成功路径。
- **可独立测试**:提交一个会成功的作业 → 它出现在"数据管线" → 状态自动走到成功 → 展示产物位置。
- **验收场景**:
  1. **Given** 在创建作业填好源与参数 **When** 提交 **Then** 作业被接受并出现在"数据管线"。
  2. **Given** 有运行中作业 **When** 在界面停留 **Then** 状态**自动**更新到终态,无需手动刷新。
  3. **Given** 作业成功 **When** 查看 **Then** 展示产物的**位置 / URI**(本轮可见不可下载,见 Out)。

### User Story 6 — 排查失败的数据准备作业(P2)

作为用户,当作业失败时,我要能在界面定位它并看懂失败原因,以决定下一步。

- **Why this priority**:失败是作业功能不可分的另一半;原型把"失败"做成一等筛选,说明是高频动作。与成功路径分开才能各自被证伪、不漏测。
- **可独立测试**:存在一个失败作业 → 用"失败"筛选定位 → 进详情看到失败状态 + 失败原因 + (若有)日志/产物 URI。
- **验收场景**:
  1. **Given** 数据管线有失败作业 **When** 按"失败"筛选 **Then** 列出失败作业。
  2. **Given** 一个失败作业 **When** 进详情 **Then** 展示**终态=失败 + 失败原因(error 内容)+(若有)相关 URI**;用户据此能判断下一步。

### User Story 7 — 查看我的账户(P3)

作为用户,我查看自己的身份与组织信息,确认所属企业 / 用户组 / 角色。

- **Why this priority**:辅助信息,独立小切片。
- **可独立测试**:打开"我的账户"看到用户 / 企业 / 用户组 / 角色。
- **验收场景**:
  1. **Given** 已登录 **When** 打开"我的账户" **Then** 显示用户、所属企业(显示名)、所属用户组、角色;**不暴露内部标识**。

### Edge Cases(边界 / 异常)
- 会话操作中途过期 → 引导重新登录,不白屏 / 不报错堆栈。
- 后端不可用 / 网络中断 → 友好提示 + 可重试,不卡死。
- 无任何可访问数据时 → 列表 / 目录呈现明确**空状态**并给下一步引导("去上传"),而非空白。
- 跨企业 / 跨组数据 → 任何列表 / 详情 / 目录**永不出现**。
- 上传超大 / 中断 / 重名 → 进度可见、可重试、不产生假成功 / 冲突有提示。

## Requirements *(必填)*

### 功能需求(可测)
- **FR-001**:系统 MUST 要求登录后才能访问任何数据 / 作业页面。
- **FR-002**:系统 MUST 只展示用户**有权访问**的数据(列表 / 详情 / 目录),MUST NOT 在界面侧自行放宽授权。
- **FR-003**:系统 MUST NOT 让用户选择上传的目标用户组;归属由用户身份决定。
- **FR-004**:系统 MUST NOT 在界面暴露登录凭据 / 令牌,也 MUST NOT 暴露内部标识(如 e- / g- 前缀 ID)。
- **FR-005**:用户 MUST 能上传原始数据集;上传 MUST 显示进度、支持失败重试,且**仅在数据真正落地后**才标记为可用。
- **FR-006**:越权请求 MUST 被(后端)拒绝且界面**不提供越权入口**(如不让选他人组);被拒时给可理解提示且**无副作用**。
- **FR-007**:用户 MUST 能**从所看的数据集/目录项一键发起作业**(源预选);亦可在创建作业页手选源。
- **FR-008**:用户 MUST 能创建作业,系统 MUST 自动跟踪作业到终态(系统判定,非靠刷新);成功 MUST 展示产物**位置/URI**,失败 MUST 展示**失败原因**且可被筛选定位。
- **FR-009**:数据集 MUST 展示格式 / 样本数 / 大小等关键属性;信息缺失时 MUST 优雅占位而非报错。
- **FR-010**:用户 MUST 能按"企业 → 数据源 → 数据域"层级浏览数据目录,层级 MUST 可展开 / 折叠。
- **FR-011**:导航 MUST 可折叠。
- **FR-012**:任何列表 / 目录在无可见数据时 MUST 呈现明确空状态 + 下一步引导。
- **FR-013**:系统本轮 MUST NOT 提供:SQL 查询 / 另存为 · 删除 / 重命名 / 改属性 / 打标签 / 取消 / 重跑 · 下载 / 导出 · 权限策略管理 · 数据探查助手(均 vN+)。

### 关键实体(概念级)
- **用户 / 账户**:当前用户及其组织上下文(企业、用户组、角色)。
- **数据集**:用户管理的数据资产(名称、描述、归属、格式、样本数、大小、是否共享、位置、创建信息);上传产生的原始数据集是其一种形态。
- **数据目录项**:平台已登记的数据资产,按"企业 → 数据源 → 数据域"层级组织,带归属 / 位置信息。
- **作业**:一次数据准备运行(源数据集、状态、产物位置、失败原因)。

## Success Criteria *(必填)*

> 可度量、技术无关。
- **SC-001**:新用户从登录到看到自己的数据集列表 ≤ 3 次操作、≤ 10 秒(常规网络)。
- **SC-002**:用户**无需任何命令行 / 脚本**,纯经界面即可完成"上传 → 发现/选源 → 创建作业 → 跟踪到产物"的完整闭环。
- **SC-003**:跨企业 / 跨用户组数据、以及内部标识(e- / g- ID),在任何用户视图中出现次数 = **0**。
- **SC-004**:运行中作业状态**无需手动刷新**即更新到终态;失败作业可经筛选在 ≤ 2 步内定位并看到失败原因。
- **SC-005**:GB 级文件可经界面上传完成,全程显示进度;单点失败可重试而不必从头重传。
- **SC-006**:数据域核心流(登录 / 数据集 / 上传 / 目录 / 发现并建作业 / 跟踪 / 排障 / 账户)可在浏览器端到端演示通过(出口⑤ 验收)。

## Assumptions(假设与依赖)
- v1 一个用户只属**一个企业、一个用户组**,上传归属由身份唯一确定(无需选择)。
- 复用既有登录 / 身份体系(账号由企业分配),本 plan 不新建账号体系。
- **v1 界面不按角色分化交互**;角色仅作展示(US7)。角色相关的管理能力随管理动作一并 vN+。
- 目标环境为**桌面浏览器**;移动端 vN+。
- 数据集的格式 / 样本数 / 大小由后端提供;后端补齐前界面以占位呈现。**血缘**后端尚无,详情页本轮不展示。
- 跨用户组授权共享 = v2;数据集 / 作业的删改/取消/下载 = vN+(后端能力未就绪)。
- 依赖已交付后端:登录会话、数据目录 / 数据集查询、作业提交与查询(含失败原因)、数据上传能力。
