# Spec — catalog-driven 数据集模型(一等条目 + 血缘)+ 管线从 catalog 读取

> WHAT / WHY。零实现细节(端点/schema/技术栈归 design)。地基决策见将落的 [ADR-023](../../../adr/)(catalog-driven 数据集 + 血缘;扩展 [ADR-016](../../../adr/ADR-016-gravitino-tenancy-mapping.md),执行 [ADR-018](../../../adr/) 的 S2a)。

## 出口与范围
- **关哪个**:把"数据集"从隐式约定(管线按命名约定猜 OSS 路径、raw 不在目录、processed 才进目录)升级为 **catalog 为唯一真相源**——每个数据集(原始/已处理)都是数据目录里的一等条目、带位置与血缘;管线**按名查目录拿位置**来跑,而非猜路径。打通"下载 → 上传 → 显式注册 → 从对象存储跑管线 → 注册派生产物"的完整本地链路。
- **In**:① 数据集一等条目(原始 + 已处理同模型)+ **血缘**(派生自哪个数据集)② 用户**显式注册**数据集到目录(记录位置)③ 管线**输入=按名查目录拿位置**、**输出=注册一个派生条目** ④ 目录/schema **显式 bootstrap**(一次性)⑤ 前端:注册按钮 + 创建作业从目录选源 + 数据集页显示格式/血缘。
- **Out / 推迟(v-next,带理由)**:
  - **二次处理已处理(Lance)数据集** —— 需要管线多一条 Lance→中间格式的读取路径,本轮 ingest 只做原始(webdataset tar);**数据模型本轮即带血缘字段**,将来补 ingest 即可,无需重构。
  - **多 catalog / 多数据域** —— v1 单 catalog(data)/单 schema(datasets);数据域模型待「数据目录」成熟。
  - **跨组共享发现 / 细粒度权限** —— 留 Cerbos(本轮授权沿用 can() 现状)。
  - **Organizations 作企业** —— 独立地基线([调研已成文](../../spikes/2026-06-23-kc-organizations-vs-groups.md))。
- **与现状对齐**:企业=metalake(`e_XXXX`)、catalog=`data`、schema=`datasets`([ADR-016](../../../adr/ADR-016-gravitino-tenancy-mapping.md))不变;本轮在该 schema 下让 fileset 表达"一等数据集 + 格式 + 血缘"。

## 用户故事(按优先级,可独立测试)

### US0 — 企业的目录骨架被显式建立(P1,前置)
**Why P1**:没有目录骨架(企业级容器 + 数据域),数据集无处可注册;这是 US1~US3 的前置。显式建立(非"注册时偷偷建")。
**可独立测试**:对一个新企业跑一次 bootstrap → 其目录骨架存在;此前浏览该企业目录返回空(不报错)。
- **AC1**:Given 一个尚无目录骨架的企业,When 运维跑一次 bootstrap,Then 该企业的目录骨架(容器 + 数据域)被建立,数据集可往其下注册。
- **AC2**:Given 骨架尚未建立,When 我浏览该企业的数据目录,Then 返回**空**而非报错。

### US1 — 显式把上传的数据集注册进目录(P1)
**Why P1**:这是 catalog-driven 的地基——没有"注册即记录位置",管线就无从按名查位置。只做 US1+US3 即是可演示 MVP(上传→注册→管线读到)。
**可独立测试**:上传一份原始数据 → 点注册 → 它作为"原始"一等条目出现在目录里,带位置与归属。
- **AC1 (G/W/T)**:Given 我已上传一份原始数据,When 我对它点「注册」,Then 它作为一个**原始**数据集出现在数据目录中,带名称、格式(原始)、**归属(owner=我,上传者)**,且其数据位置被系统记录。
- **AC2**:Given 同名数据集已注册,When 我再次注册,Then 系统**拒绝并提示已存在**(不静默覆盖,不产生重复条目)。
- **AC3**:Given 我未提供任何位置,When 注册,Then 系统**用我身份确定的位置**记录(我无法把它指向不属于我的位置)。

### US2 — 管线按数据集名从目录读取来跑(P1)
**Why P1**:把"管线从对象存储跑通"做对的核心——管线不再猜路径,而是查目录拿位置。
**可独立测试**:对一个已注册的原始数据集创建作业 → 作业从目录解析到它的位置 → 读取并处理成功。
- **AC1**:Given 一个已注册的原始数据集,When 我对它创建数据准备作业,Then 管线**按数据集名从目录解析其位置**并据此读取数据(我不需要手填任何路径)。
- **AC2**:Given 我请求处理一个目录里不存在的数据集,When 创建作业,Then 系统**明确报"数据集不存在/不可读"**(不产生指向空位置的失败作业)。
- **AC3**:Given 我对不属于我可读范围的数据集创建作业,When 解析位置,Then 被**拒绝**(隔离不被绕过)。

### US3 — 已处理产物作为派生数据集注册、独立可用(P1)
**Why P1**:闭合链路(产出可见可用),并把"血缘"立起来。
**可独立测试**:作业成功后,其产物作为"已处理"数据集出现在目录,记录"派生自原始数据集"。
- **AC1**:Given 数据准备作业成功,When 我注册其产物,Then 它作为一个**已处理**数据集出现在目录,带格式、**样本数(由系统取自作业结果、非我手填)**、**血缘(派生自哪个数据集)**。
- **AC2**:Given 一个已处理数据集,When 我查看它,Then 我能看到它**独立可用**(有自己的位置)且知道它**来自哪个原始数据集**。
- **AC3**:Given 一个已处理数据集,When 我想对它二次处理,Then 系统**明确告知该能力暂未提供(v-next)**,而不是给一个会失败的入口(诚实占位)。

### US4 — 目录/数据集页呈现一等条目 + 血缘(P2)
**Why P2**:让上面三条在界面上可见、可操作;但晚于"链路先通"。
**可独立测试**:界面上能看到数据集的格式(原始/已处理)与血缘,创建作业能从目录选源。
- **AC1**:Given 目录里有原始与已处理数据集,When 我看数据集/数据目录页,Then 每个条目显示**格式(原始/已处理)**;已处理的显示其**来源数据集**。
- **AC2**:Given 我要创建作业,When 选择源,Then 我从**已注册的数据集里选**(不再手填路径)。
- **AC3**:Given 缺某些元数据字段,When 渲染,Then 显示「—」而非报错(读路径 null-safe)。

### Edge Cases
- 当数据目录/schema 尚未建好(空企业)时注册或浏览会怎样?→ 浏览返回**空**而非报错;注册前提是目录骨架已 bootstrap(见 design)。
- 当注册的数据集名不合法(非法字符)时会怎样?→ 显式拒绝(沿用现有命名校验)。
- 当作业引用的源数据集**位置存在于目录但对象不在对象存储**时会怎样?→ 作业失败并给出"源数据缺失"原因,不产生空产物。
- 当两个作业并发注册同名派生产物时会怎样?→ 第二个得到"已存在"冲突,不产生重复条目。
- 当一个已处理数据集被当作"原始"格式去跑当前管线会怎样?→ 因格式不符,系统应拒绝/明确报错(v1 管线仅吃原始 webdataset tar)。

## 功能需求(MUST,可测)
- **FR-001** 每个数据集 MUST 是数据目录里的**一等条目**,带:名称、**格式/种类(原始 / 已处理)**、数据位置、**归属(owner=上传用户,ADR-024)**、可见性、样本数/大小(可空)。
- **FR-002** 已处理数据集 MUST 记录**血缘**:它**派生自哪个数据集**。
- **FR-003** 注册 MUST 是**用户显式动作**;系统 MUST 用**调用者身份**确定/校验数据位置,使用户**无法把数据集指向不属于自己的位置**。
- **FR-004** 管线 MUST 以**数据集名**为输入,**从目录解析其位置**后读取;MUST NOT 要求用户手填存储路径;源数据集不存在/不可读 MUST 明确报错。
- **FR-005** 管线产出 MUST 作为**新的派生数据集**注册(带血缘指向输入);产出 MUST **独立可用**(有自身位置)。
- **FR-006** 数据目录/schema MUST 通过**显式 bootstrap**(一次性)建立;空企业浏览 MUST 返回空而非报错。
- **FR-007** 系统 MUST 拒绝**重复注册**(同名)与**非法名称**;读路径 MUST 对缺失字段 null-safe(显「—」不崩)。
- **FR-008** 本轮 MUST NOT 破坏既有 CI 与既有数据集读写;授权沿用现有 `can()`(细粒度留 Cerbos)。
- **FR-009** 界面 MUST 呈现数据集的格式与血缘,创建作业 MUST 从已注册数据集选源;二次处理已处理数据集 MUST 以"暂未提供(v-next)"诚实呈现,不给会失败的入口。
- **FR-010** 已处理数据集的**样本数取自作业结果 `rows_written`**(管线权威):**界面 MUST 只读地从作业取值、用户不可编辑**(UI 层强制)。服务端注册时拿不到作业(作业在 data-pipeline、注册在 metadata),故 v1 不做服务端独立核验;**服务端权威(注册引用 job_id 跨服务回填)标 v-next**。

## 关键实体(概念)
- **数据集(Dataset)**:目录里的一等条目。属性:名称、格式/种类(原始/已处理)、位置、血缘(来源数据集)、**归属(owner=上传用户;group 退为访问维度,留 Cerbos)**、可见性、样本数/大小。
- **格式/种类**:原始(webdataset tar)/ 已处理(Lance)。决定能否被当前管线消费。
- **血缘(derived_from)**:已处理数据集指向其来源数据集的引用。
- **数据准备作业**:以一个数据集为输入、产出一个派生数据集的处理过程。
- **目录骨架**:企业级 metalake + catalog + schema,数据集条目挂其下。

## Success Criteria(可度量、技术无关)
- **SC-001**:上传一份原始数据 → 显式注册 → 它**出现在数据目录**(原始,带位置与归属);重复注册被拒。
- **SC-002**:对该原始数据集创建作业(**不手填任何路径**)→ 管线**从目录解析位置并成功读取处理**。
- **SC-003**:作业产物注册后**作为已处理数据集出现**,且**记录派生自该原始数据集**;其位置独立可用。
- **SC-004**:空企业浏览数据目录返回**空表**(不报错);引用不存在的源数据集创建作业**明确报错**(无空产物)。
- **SC-005**:界面上每个数据集**显示格式**;已处理显示**来源**;创建作业**从已注册数据集选源**;二次处理已处理数据集显示"暂未提供"。
- **SC-006**:无法把数据集**指向不属于自己的位置**;管线无法读取**不可读**的数据集(隔离不被绕过)。
- **SC-007**:既有质量门禁(生成/静态检查/测试)**仍全绿**;既有数据集读写不回归。
- **SC-008**:端到端冒烟(coco 一小片)**全程跑通**:下载→上传→显式注册→管线从目录读→处理→注册派生→两条目可见。

## Assumptions
- v1 管线只消费**原始 webdataset tar**;二次处理已处理(Lance)需 Lance 读取路径,**显式 v-next**。
- 企业/catalog/schema 维持单层(metalake=企业、catalog=data、schema=datasets,ADR-016);多 catalog/数据域 v-next。
- 授权沿用现有 `can()`(企业硬隔离 + 组);跨组共享发现/细粒度留 Cerbos。
- "位置由身份确定"沿用上传的服务端钉死范式(ADR-020):注册原始时位置 = 调用者身份对应的对象存储前缀,客户端不能任意指定。
- 前端建在 `s1-plan8b-frontend` 分支(前端代码所在);本特性与 8b 一并验收/合并或紧随。
- 数据持久化、本地环境单一源等沿用已合并的 env-config(阶段 2)。
- 契约采**直接破坏性变更**(v1 未 GA、无外部消费者):同 PR 改内部消费者 + 更新 oasdiff 基线(owner 拍;详见 design + ADR-023)。
- catalog-driven 读 = 本轮**新增** pipeline→metadata 运行时依赖 + bearer 传播(承重墙,Plan 首任务/探针;详见 design DoR#4)。

## 修订记录(as-built)
- **2026-06-24 已实现并合并 main**:catalog-driven 全链路 live 验收通过(上传→注册→建作业→管线从 catalog 读 `s3a://` 位置跑→注册派生产物→数据集/目录可见)。
- **归属模型改为 owner(ADR-024,本特性内一并改)**:数据集归属 = **上传/创建它的用户(owner=sub)**,不再是 group;企业仍硬隔离;**group 退为访问/审计维度,跨用户分享/group 访问留 Cerbos v2**。本文上方"归属(组/用户)"已统一为"归属(owner=上传用户)"。OSS 路径随之 `e-XXXX/{user}/{raw,processed}/…`(不再按 group)。
- **scheme 二元性(as-built)**:同一物理对象,lance 读写用 `s3://`(object_store),Gravitino fileset location 记 `s3a://`(HCFS);注册端点在写 Gravitino 前转 scheme。
- **已知限制 / v-next**:UI 算子为中文标签、未映射到真实 Data-Juicer 算子(勾选会使 DJ 失败,当前用默认算子集);数据预览 / 列式 schema(Lance Arrow)未做。
